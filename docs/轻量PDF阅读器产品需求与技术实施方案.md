## 1. 项目概述

### 1.1 项目简介

LitePDF 是本人独立完成的桌面 PDF 阅读器。软件支持打开本地 PDF、多标签并行阅读、缩放与翻页、常用批注、全文搜索、打印与另存，并提供 Windows / macOS 安装包。安装后可在资源管理器中通过右键菜单调用，也可设置为系统默认 PDF 程序。

项目不以复刻福昕完整桌面套件为目标，而是围绕日常阅读场景，基于福昕 PDF WebSDK开发能力重新定义产品边界，并完成从选型、定制到安装交付的全过程。


### 1.2 选题背景

福昕桌面产品在阅读、编辑、表单、文档保护与格式转换等方面能力完备。就个人高频使用场景而言，多数需求集中于「快速打开、顺畅阅读、少量批注」，完整套件的功能广度与客户端体量并不总是匹配。

据此，本人将课题设定为：

> 基于福昕 PDF 开发工具包，而非改造现成客户端，实现一款仅保留阅读与常用批注能力的轻量桌面阅读器，并具备可安装、可稳定使用的交付形态。

课题需同时回答三类问题：产品上如何界定「轻量」；技术上如何正确使用福昕 SDK 完成核心能力；工程上如何将 SDK 嵌入桌面应用并解决多文档、安装包与系统集成中的实际障碍。

## 2. 福昕产品与模块使用说明



### 2.1 产品选用

本项目的 PDF 核心能力来自福昕 **PDF SDK for Web**（当前使用 11.x，npm 包名为 `@foxitsoftware/foxit-pdf-sdk-for-web-library`）。该产品面向网页与混合应用开发，提供 PDF 解析、渲染、批注、搜索、打印及可扩展的阅读器界面框架。

本人未自行实现 PDF 引擎，亦未将福昕能力二次封装为另一套对外 SDK。工作重点在于：在理解产品边界的前提下完成选型；按官方扩展机制完成界面裁剪与功能组装；解决 SDK 进入桌面安装环境后的工程问题。

职责划分如下：

- **福昕 PDF SDK for Web**：负责打开 PDF、页面渲染、批注、搜索、打印、文档属性等文档能力；
- **LitePDF 应用层**：负责窗口管理、多标签、最近文件、安装包、系统文件关联与更新检查。

### 2.3 功能裁剪原则

完整 Web 阅读器还可启用编辑、表单、文档保护、文件包等能力。本项目根据选题边界予以关闭，使交付物保持「阅读器」定位，而非缩略版编辑套件。该裁剪既是产品决策，也是对 SDK 定制能力的运用。

### 2.4 应用层自研部分

以下能力由本人实现，用于将 SDK 组织为完整桌面产品，并不替代福昕引擎：

- 多标签工作台、开始页与最近文件管理；
- 标签切换时的阅读位置保存与恢复；
- 安装包构建、更新检查、系统右键打开及默认应用引导；
- SDK 适配层，使业务代码不直接依赖全局 PDFUI 实例。

## 4. 关键问题与解决过程

官方示例通常覆盖「在网页中打开一份 PDF」。本项目面向可安装的多标签桌面阅读器，实施过程中主要解决了以下问题。

### 4.1 功能面裁剪

默认界面接近完整阅读编辑套件，与「轻量阅读」目标不符。本人通过 Appearance 与布局模板，仅保留阅读与批注相关能力，侧栏限定为缩略图、书签、注释与搜索。交付界面呈现为独立阅读器，而非官方演示的简单换皮。

### 4.2 多文档并行打开

初期在打开第二份 PDF 时出现失败，日志表现为引擎相关对象读取异常。排查后确认：每一 PDFUI 实例须配备独立的 JR Worker，多标签不得共用。随后调整为「一标签一 PDFUI、一 Worker」；欢迎页仅预热首个 Worker 以缩短首开时间，其后标签各自创建。该问题于 v0.1.4 解决，多标签并行阅读趋于稳定。

### 4.3 安装版打开失败

开发环境下应用与 SDK 通过本地 HTTP 服务加载，行为正常；安装后若按本地文件协议加载 SDK，则 Worker 与插件资源获取失败，表现为空白页或打开失败。解决方案是：在生产环境于本机 `127.0.0.1` 启动仅服务本地的静态资源服务，以 HTTP 方式同时提供应用前端与福昕 SDK。该方案于 v0.1.5 落地，使安装版与开发环境的打开行为保持一致。

### 4.4 标签切换丢失阅读位置

在标签间切换时，曾出现界面闪烁并回到文档首页。原因在于以移除显示的方式隐藏非活跃面板后，引擎视口尺寸变为零，内部阅读状态被重置。调整为叠层隐藏以保持容器尺寸，并在切换时保存、恢复页码、缩放与视图模式。该问题于 v0.1.6 解决。

### 4.5 系统级打开方式

仅支持应用内打开，尚不足以满足日常使用习惯。v0.1.7 起，安装过程注册 PDF 文件类型，Windows 提供「使用 LitePDF 打开」右键菜单；应用内提供设为默认阅读器的入口。受操作系统限制，默认应用须由用户在系统设置中确认，软件不得静默抢占。

上述问题构成完整实施链条：明确选题与福昕模块用法之后，针对 SDK 与桌面环境结合过程中的实际障碍完成定位与修复，并持续发布可验证版本。

## 5. 用户与使用场景



### 5.1 目标用户

在 Windows 或 macOS 上阅读、批注本地 PDF 的个人用户。本项目不面向企业账号体系与云文档协作。

### 5.2 核心场景

1. 通过开始页、拖放、右键菜单或默认应用打开一个或多个 PDF；
2. 在多标签之间切换，并保留各自阅读位置；
3. 完成高亮、画笔、图章等批注后另存；
4. 从最近文件列表找回文档，并对失效项予以标识；
5. 在应用内检查新版本并下载对应安装包。

### 6.3 阅读与批注

阅读能力包括：手型工具、缩放、页码导航、上一视图与下一视图、单页/连续/对开布局、缩略图、书签及滚轮缩放。上述能力均建立在福昕阅读控件与相关插件之上。

批注能力包括：撤销与重做、文本高亮与区域高亮、画笔与局部擦除、打字机/文本框/标注、绘图、下划线与删除线等文本标记、图章与墨迹签名。

顶栏提供搜索、打印、另存为及更多菜单；更多菜单可进入注释列表、演示播放与文档属性。

### 6.4 打开失败与授权提示

- 加密文档弹出密码输入；
- 不对用户展示纯错误码，以免遮挡 SDK 授权相关提示；
- 无明确错误文案时，统一提示「PDF 打开失败，请重试。」



### 6.5 更新

安装版启动后静默检查 GitHub 最新发布；仅当存在适用于当前系统的安装包时提示下载。更新说明过长时，下载操作仍保持可见。

## 7. 总体架构

```
Electron 主进程
  窗口、文件对话框、最近文件、更新检查、本机静态服务、PDF 文件关联
        │
        ▼
Vue 3 渲染进程
  开始页、标签栏、关于与更新界面
        │
        ▼
适配层
  ViewerSession（每标签） → FoxitViewerAdapter（唯一创建 PDFUI）
        │
        ▼
福昕 PDF SDK for Web
  JR Worker + UIExtension + 按需插件
```

业务组件不直接持有全局 PDFUI，以便更换授权、调整界面裁剪，并清晰管理会话生命周期。

主要目录约定如下：`electron/` 为主进程；`src/foxit/adapter` 为适配层；`src/foxit/appearance` 为布局定制；`src/foxit/controllers` 为自研控件绑定；`src/foxit/warmup.ts` 负责引擎预热。

## 8. 关键技术方案



### 8.1 多标签与阅读进度

采用一标签一 PDFUI 的模型。非活跃标签以叠层方式隐藏，避免因容器尺寸归零导致引擎状态丢失。标签失活时保存页码、缩放、旋转与视图模式，激活时予以恢复。加载遮罩仅在文档首次打开时展示。

### 8.2 安装版资源加载

生产环境在 `127.0.0.1` 提供前端资源与 `foxit-lib`，使 Worker 与插件仍通过 HTTP 获取资源。静态服务路径限制在应用资源目录内，防止越权读取。

### 8.3 Worker 隔离与预热

欢迎页预热 SDK 脚本与 License，并预创建一个 Worker，仅允许第一个 PDF 标签认领；其后标签各自创建 Worker。打开完成以 SDK 成功回调为准关闭加载遮罩。

### 8.4 界面裁剪与插件配置

布局模板保留主页工具条与批注工具条。启用插件包括：`thumbnail`、`search`、`print`、`undo-redo`、`file-property`、`full-screen`。自研 Controller 在创建 PDFUI 之前完成注册。

### 8.5 授权管理

授权读取顺序为：本地 `license-key.js`、环境变量、默认占位配置。密钥文件不纳入版本库。更换授权后需重新打包。

### 8.6 安装包体积控制

SDK 仅通过安装包资源目录携带一份 `foxit-lib`，避免与应用压缩包重复打包；不携带完整外部字体包；界面词条与图章资源以中英文为主。

### 8.7 文件关联

Windows 在安装与启动阶段写入「使用 LitePDF 打开」；设为默认应用需用户在系统设置中确认。macOS 通过安装包声明 PDF 文档类型，应用内尝试设为默认，失败时引导用户通过系统简介完成更改。开发模式不写入系统注册信息。
